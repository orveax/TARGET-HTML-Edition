# ORIGEX — ThemeForest Benchmark | 2026-08

Purpose: extract product-design lessons from successful ThemeForest HTML templates without turning ORIGEX into a generic multipurpose clone.

## Benchmarks Observed

### Canvas
Market signal:
- Very high lifetime sales.
- Large demo count.
- Large UI element library.
- Bootstrap 5.3.
- Modular JS.
- RTL compatibility.

What ORIGEX should learn:
- Buyers value breadth, reusable elements and documented variation.
- RTL should be structural, not a late patch.
- A visible Elements/Components library increases perceived product value.

What ORIGEX should not copy:
- Multipurpose breadth across unrelated industries.
- Huge demo count with weak vertical focus.

### Porto
Market signal:
- Very high lifetime sales.
- Hundreds of HTML files.
- Many demos/homepages.
- Bootstrap 5 + SCSS.
- Style-switcher/customization emphasis.

What ORIGEX should learn:
- Easy customization is a selling feature, not only an engineering detail.
- A central customization mechanism is valuable.
- Strong documentation and mature versioning matter.

ORIGEX response:
- `config.js` simple customization layer.
- CSS design tokens.
- Clear Additional Features insertion documentation.

### Crafto / Litho
Market signal:
- Large numbers of ready websites/templates/elements.
- Strong responsive presentation.
- Bootstrap-based component systems.
- Forms and modern interaction are visible selling points.

What ORIGEX should learn:
- Marketable templates sell a system, not isolated pages.
- Buyers expect polished form, navigation, CTA and content patterns.

### Bexon
Market signal:
- Multiple homepages and many HTML files.
- Sticky header.
- Mega menu.
- SEO-friendly positioning.
- RTL support.
- Modern animation.
- Well-documented positioning.

What ORIGEX should learn:
- Multiple home perspectives help buyers see category fit.
- Home variations should have different commercial purposes, not just different hero images.
- Mega menu, responsive behavior and RTL are expected premium features.

## ORIGEX Strategic Position

ORIGEX should compete through:
- Vertical specificity rather than demo count.
- Arabic-first RTL rather than generic RTL compatibility.
- B2B food-trading data and conversion patterns.
- Main + Additional feature architecture.
- Beginner-friendly `config.js`.
- Premium but restrained interaction.
- Strong documentation and component library.

## Deliberate Non-Goals

- Do not chase 100+ demos.
- Do not add unrelated industries.
- Do not add a page builder in V1.
- Do not add ecommerce/cart complexity in V1.
- Do not add heavy animation libraries merely to look modern.

## Marketplace Preparation Lessons

- Main files and documentation must be easy to view, edit and understand.
- Code should follow current best practices and be validated.
- A high-quality live preview is part of the buying experience for web themes.
- Assets in the downloadable item require appropriate redistribution rights.
- Preview-only assets still require commercial-use rights and must be disclosed as preview-only.
- Documentation should assume the buyer may have limited coding knowledge.

## Resulting ORIGEX Product Principles

1. Feature-Rich, Demo-Disciplined.
2. Arabic-First, English-Complete.
3. Vertical Before Multipurpose.
4. One Global Design System, Page Design Profiles.
5. Static-First Performance.
6. Beginner-Friendly Customization.
7. Document While Building.
8. Licensing Tracked Before Packaging.
