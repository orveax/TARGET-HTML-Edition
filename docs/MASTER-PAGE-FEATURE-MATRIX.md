## Feature Model

Every page is designed with three layers:

1. **Main Features** — visible in the primary demo and required for the page to fulfill its commercial purpose.
2. **Additional Features** — production-ready reusable sections/components shipped with the template but not necessarily enabled in the primary demo. Buyers add them manually using the documentation.
3. **Not V1** — features intentionally excluded to protect quality, speed, and product focus.

Additional Features must never be filler. Each optional block must solve a real B2B food-trading use case and must be reusable across more than one page where practical.

## Manual Installation Standard

Every Additional Feature must include in documentation:

- What the component is for
- Which pages it can be used on
- Required HTML snippet
- Required CSS class(es)
- Optional JS dependency if any
- Arabic RTL behavior
- English LTR behavior
- Responsive notes
- Accessibility notes
- Demo screenshot or visual reference
- How to remove it cleanly

## Language & Direction Gate

Every Main or Additional Feature must pass:

1. Arabic content first
2. `lang="ar" dir="rtl"`
3. Tajawal hierarchy
4. RTL spacing using logical properties where practical
5. Directional icons/arrows reviewed
6. Mixed Arabic/English data reviewed
7. English counterpart created
8. `lang="en" dir="ltr"`
9. Manrope hierarchy
10. Mobile / tablet / desktop behavior checked in both languages

## Product Rule

ORIGEX must feel richer than a single Bootstrap demo while remaining more disciplined than a bloated multipurpose template. The primary demos stay focused; depth is delivered through reusable components, optional sections, documentation, and multiple vertical-specific page layouts.
