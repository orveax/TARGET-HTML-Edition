# ORIGEX — PG28 404 | Page Design Profile V1

Product ID: ORX-P01  
Milestone: M6 — Support / Utility / Components  
Canonical file: `404.html`  
Status: PS6 — FROZEN FOR BUILD

## Purpose
Provide a branded bilingual recovery page for missing or moved URLs. The page must explain the error clearly, preserve ORIGEX visual quality, and give visitors practical routes back into the commercial experience without inventing server state or redirect behavior.

## Canonical Content Authority
Arabic Master:
- H1: `الصفحة غير موجودة، لكن المسار واضح.`
- Support: `ربما تغير الرابط أو تم نقله. ارجع إلى المنتجات أو الموردين أو تواصل معنا للوصول للمعلومة المطلوبة.`
- CTA: `العودة للرئيسية` / `استعرض المنتجات`

English Adaptation:
- H1: `This page is unavailable, but the route is clear.`
- CTA: `Back to Home.`

Frozen V1 Scope Main Features:
- branded error state
- clear explanation
- home link
- search / recovery links
- contact fallback

## Recovery Architecture
Primary actions:
1. Home
2. Products

Searchable recovery destinations:
- Home
- Products
- Suppliers
- Resources
- FAQ
- Contact

Rules:
- Recovery search is local UI only; no remote search service or network request.
- Recovery cards remain visible and usable when JavaScript is unavailable.
- With JavaScript enabled, search filters the six approved destinations, updates a result count, exposes an empty state, and supports reset / Escape clear.
- Optional `?q=` state may hydrate the local recovery search and is preserved across AR/EN language links when non-empty.
- Contact is the explicit fallback when the visitor cannot locate the intended destination.
- No automatic redirect, guessed destination, browser-history dependency, or fabricated “requested URL” output.

## Error / Deployment Contract
- `404.html` is the branded error document; HTML alone cannot set an HTTP status code.
- Production deployment must map missing routes to this page while returning an actual HTTP `404` response.
- The template does not claim that Cloudflare, Apache, Nginx, WordPress, or another server has already been configured.
- No countdown, tracking pixel, analytics event, error ID, ticket ID, or server diagnostic is fabricated.

## Page Composition
1. Standard Global Navigation V1 shell.
2. Branded 404 hero with large numeric marker, canonical H1/support, and two canonical CTAs.
3. Recovery search block with accessible search field and live result count.
4. Six recovery route cards using existing registered ORIGEX components/icons.
5. Empty state with reset action + Contact fallback.
6. Compact “Still looking?” contact CTA.
7. Standard Global Footer V1.

## UX / Accessibility
- Arabic RTL and English LTR are first-class.
- Exactly one H1.
- Search label remains explicit; placeholder is not the sole label.
- Result count uses a polite live region.
- Empty state is announced without trapping focus.
- Reset is keyboard operable; Escape clears an active query.
- Recovery links retain descriptive accessible names.
- Standard keyboard navigation, skip link, mega menu and mobile drawer remain intact.
- Responsive verification: 390 / 820 / 1366 / 1536.
- Reduced-motion behavior follows the global system.

## SEO / Page Identity Contract
Classification: **NOINDEX**.

Required:
- `<meta name="robots" content="noindex,follow">`
- no Product / Offer / Review / LocalBusiness / Organization structured-data claims
- no fake SearchAction or site-search schema because recovery search is local page filtering only
- no canonical or hreflang requirement for the error document; missing runtime URLs are not canonicalized to the demo 404 asset
- Open Graph metadata may describe the branded error page for direct preview only, but does not change NOINDEX status

Production note:
- HTTP `404` response is a deployment/server concern and must be documented separately from HTML metadata.

## Design Direction
- Premium but restrained utility page, not a decorative dead-end.
- Large `404` marker may use brand typography/graphic field as a visual anchor.
- Recovery actions carry stronger hierarchy than the error number itself.
- Use existing ORIGEX tokens only; no new color family, font, dependency, illustration library or third-party image.
